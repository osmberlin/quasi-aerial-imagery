# Results log

## How to use

Append-only going forward: one row per run that produces a number or a judgement, including failed and crashed runs; new rows at the bottom; never rewrite an old row. If a row turns out wrong or superseded, add a correction row and say so. Each row says how its number was obtained: the Evidence column gives the quality of the evidence (legend below) and the Source column names the artefact, script or document the number comes from. "run log" and "run output" mean the log or output files of the run, which are not published; "experiment note (not public)" and "research note (not public)" are working notes that are not part of this repository. Rows before 2026-10-26 were condensed for publication: rows of earlier pipelines and superseded rows are shortened, internal remarks removed; IDs are unchanged. The log has no rows R-183 and R-184.

**Evidence legend**
- `V`: number read from an artefact file (run report, log, GeoTIFF, metrics file).
- `D`: stated in a document only, no artefact re-read.
- `C`: only claimed in a working session (tool output not preserved).
- `M`: document and artefact disagree. Both values are kept in the row.

## What no result covered by 2026-10-13

Later rows close some of these gaps (external reference comparison: R-132, R-151, R-162, R-175; tape check: R-191, R-202; video ingestion: R-107, R-177). The rest was still open when this list was written:

- **Absolute accuracy of the early pipelines.** The only reference of the LingBot-era outputs was GPS, with per-chunk residuals of 3.7-9.7 m; internal consistency checks (`precision_qa`) cannot show accuracy.
- **Relative distance checks.** No tape-measure or known-length check existed on any output; the 10 cm target (D-053) was unmeasured.
- **Clean LingBot batch.** No batch output after 2026-07-07; `stitch_georef` was never wired into the pipeline; the 5 cm ground-seam check (D-052) was never run.
- **Scale of the early pipelines.** Largest runs were 30 frames; depth-ortho ran on 2 and 10 frames only; chunk overlap of 2 or more and multi-yaw LingBot input were never tested on real data.
- **Helmet mask effect.** No with/without comparison on any final GeoTIFF; only the self-check leak score and overlays; only four reference sets were used, with no held-out frames and no other rig.
- **Unmeasured parameter effects.** LingBot `conf_threshold` 5.0, nadir cone 38 versus 25 degrees (D-021, D-026), the 2 m cut against the 3.0 m height cap (D-027), gravity alignment against a GPS fit for 10 cm use (D-034).
- **ODM alternatives.** No fisheye ODM run and no QA-passed equirectangular ODM result; the advised 12 GiB Docker profile was never recorded as successful.
- **Rust `geo360` on this machine.** The binary did not load (libgdal version mismatch); `orthorectify` and `qa_orthophoto.py` were not re-run.

## Known doubts about early recorded results

### Circular or self-referential validation
- The helmet `leak_score` is computed on the boundary the algorithm produces, and the same metric serves as acceptance gate (R-045, R-051).
- Per-frame helmet offsets were chosen by minimising the leak and then checked with the same leak; the chosen dy values changed from round to round (R-055, R-057).
- The stitch "post residual" near 0 holds by construction; the GPS anchor keeps the absolute error. Synthetic tests reuse the GPS values the pipeline reads, so they check algebra, not reconstruction-to-GPS consistency.
- The sag-clamp acceptance "max outside-seam sag 80 px" is tautological, and "wrap delta 0.00" comes from pinning the endpoints (R-050). Boundary defaults (epsilon 24, lift 75) were tuned on the same four sets used for acceptance (R-049).

### Loosened thresholds and changed tests
- Worst-frame leak limits moved from 0.01 (0.02 for lpg2024) to 0.11-0.30 and later to 0.35 / 0.30 / 0.20 / 0.55; the mean-dy limit moved from 25 to 55-70; the palette radius percentile from 90 to 50.
- The background-leak threshold of the bridge auto-mask test moved from 0.10 to 0.13 to 0.14; the stitch test's injected offset was cut from 0.4 m to 0.25 m; the interchunk yaw tolerance widened from 0.2 to 0.3 degrees.
- Suite counts differ between sessions (bridge 4 to 45, helmet-mask 8 to 45, depth-ortho 12 and 14); the re-run of bridge (45), depth-ortho (14) and helmet-mask (45) tests passed (R-079 to R-081).

### Contradictions and mismatches
- Helmet leak values, boundary TV reduction and runtime differ between documents and artefacts (R-051 to R-053); knob counts differ (R-048).
- The pre-fix orthophoto dimensions and the "blue sky blob" claim are not confirmed (R-033); innen is documented as completed but failed (R-077, R-078).
- ODM extents (917 x 1,343 m; 61 x 152 m; 256 x 523 m) do not fit the documented footprints of 21 to about 541 m2 (R-012, R-023).
- Shared HQ-batch folders hold overlap-1 and night-1 outputs without a record of which run each holds (R-066 to R-075).
- Stitch pair 1-2: the reported final 0.760 m is worse than the best mid-loop value 0.589 m; the 0.01 m result for pair 0-1 has no output file (R-060, R-061). Live chunk scale factors 6.6 and 29.1 do not fit the 10-30 % scale-error hypothesis (R-065).
- Nadir exclusion: 38 degrees in the build log against 25.0 in the configuration (D-021).

### Visual claims without a recorded check
- "Zero helmet artifacts" for v5 (R-041); "vector-like lines with preserved corners" after round 2; "verified end-to-end" for the scene viewer while every screenshot was black (R-029).

### Process events that affect the record
- An ODM log and a duplicate imagery folder (about 688 MB) were deleted during the early work; their loss cannot be checked from the repository.
- Night-1 GeoTIFFs are documented as not to be trusted but remain in a shared folder, indistinguishable by path from later outputs (R-066 to R-070).
